# 16 · Plan before coding

**Time:** 15 min · **Difficulty:** core · **Shows:** the AI as a planning partner, with no code allowed

## The situation
You have a real-feeling research task (below) and a tendency, like all of us, to start typing code.
This challenge forbids it. Slide 23 of Part 1 as an exercise.

## The task to plan
> Using monthly output from a 0.1-degree global ocean model (temperature, salinity, mixed-layer depth,
> sea-ice concentration, 1958–2018), quantify how the timing of the spring mixed-layer shoaling in the
> Southern Ocean has changed, and whether it relates to the sea-ice retreat date. Produce a figure
> suitable for a paper.

## Your task
1. Paste the task and ask for **a plan only, no code**: the steps, the decisions that have to be made,
   the context the AI would need from you to write each step, the tests you would use to trust each
   step, and the main risks. Ask for it as a numbered list.
2. Read it critically. Mark anything that is wrong for *your* field (the AI knows oceanography in
   general; it does not know your model or your conventions).
3. Answer its questions in one message. Then ask for the plan again, revised.
4. Ask: "Which step is most likely to go wrong, and how would we know?"

## How to check
A good plan separates definition questions (what counts as "shoaling date"? what threshold for
"retreat"?) from engineering questions (how to handle 60 years of 0.1-degree data without reading it
all into memory), and it asks for your definitions rather than guessing. If it never asked you a
question, you got a worse plan than you could have.

Compare your revised plan to your first instinct. Did the plan change what you would have done first?

## Reflect
Planning with the AI costs ten minutes and usually surfaces one decision you had not noticed you were
making. Which one was it this time?
